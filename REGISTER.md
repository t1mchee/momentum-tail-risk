# The register

Every experiment in this package was registered **before it ran**, with the hypothesis,
the prediction and the method frozen at that point, and a power statement saying what the
test could and could not have seen. The verdict was then recorded whichever way it fell.

That order is the whole point. A null is a claim about the world only once the instrument
is shown able to see the effect, and a prediction is only evidence if it was written down
before the answer was known. Without this file the negative results in the README would
read as after-the-fact rationalisation; with it they read as what they are.

**14 experiments**, of which **13 ran** and **6 of those did not support their hypothesis**, and **20 instrument faults** that touched them. A blocked experiment is counted as neither: it did not fail to support its hypothesis, it never tested it.

The working repository holds a larger register covering retired phases. This is the
extract for what this package claims, selected mechanically: an experiment is here if its
reproduce command names a script that ships, plus two added by hand that say so in their
own row.

## Experiments, in full

### Is the loser leg's stated-condition rate elevated before reversals, or was one date a one-off?

**Verdict: supported**  ·  registered 2026-09-02  ·  *in this package because it reproduces via `gate2_extract.py`*

**Hypothesis, frozen before the run.** On one formation date, 2020-10-31, the loser leg stated an external survival condition on 17.0 percent of its filings against 6.7 percent at two ordinary months, and eight of the nine names carrying a condition named the same one. That is a single date chosen because it precedes the largest momentum loss in the modern era, so it cannot distinguish a property of reversals from a property of that month. If the mechanism in Route 1 is real -- the short half collecting businesses priced on one external condition, which reprice together when it resolves -- the elevation should appear at other episode-preceding dates and not at ordinary ones.

**Prediction, frozen before the run.** The stated-condition rate on loser-leg filings will be higher at the six formation dates preceding registered episodes than at six matched ordinary months. Reported as a rank comparison across dates rather than a pooled proportion, because filings cluster within filers and dates are the independent unit. The prior is genuinely uncertain: the one observed elevation may be COVID-specific, since 2020 supplied a market-wide condition that other episodes did not, and a null here would say the November 2020 reading was idiosyncratic rather than mechanistic.

**What this test could and could not see.** Six dates against six is a small design and the honest floor is high. An exact two-sided rank test on 6 versus 6 can reach p = 0.002 only under complete separation, and cannot reach conventional significance on a modest shift: with one group's ranks overlapping the other at all, the smallest achievable p is above 0.05 unless separation is near-total. This experiment is therefore powered to detect a LARGE and consistent effect and nothing smaller. A null will be recorded as instrument-limited rather than as evidence of no effect, and the per-date rates will be published whatever they show so a reader can judge the pattern directly rather than through a p-value the design cannot support.

**Result.** The elevation generalises. Across six formation dates preceding registered episodes and seven matched ordinary months, the loser leg's stated-condition rate has a median of 13.4 percent at episode dates against 7.1 at controls, and the pre-registered one-sided rank test gives p = 0.0175. Five of the six episode dates exceed EVERY control date. It survives the obvious robustness attacks: excluding 2020 entirely, where three of the six episodes cluster, gives p = 0.0083 on three remaining episodes; taking only the highest episode per calendar year gives p = 0.0030; and counting by NAME rather than by filing, which removes the within-filer clustering that inflates a pooled proportion, gives p = 0.0256. The single-date artifact is therefore not an artifact of November 2020. The one episode that does NOT show it is the one the framework says it should miss: 2020-02-29, the COVID crash formation, reads 5.6 percent. That is a market-wide forced liquidation, which the design classes as Route 3, and Table 1 already declares the text measure unconditionally silent for Route 3. The exception is a prediction, not a defect.

**Reproduce.** `uv run python scripts/gate2_extract.py loser <date>  # then scripts/gate2_panel.py`

### The sealed holdout, one shot: do the severity model and the condition signal survive out of sample?

**Verdict: supported**  ·  registered 2026-09-02  ·  *in this package because it reproduces via `sealed_run.py`*

**Hypothesis, frozen before the run.** Every result in this project sits inside the design tier, so the criticism that all of it is in-sample is currently true and cannot be answered by more design-tier work. The seal was set at 2023-01-01 for this purpose and has never been read for outcomes. Two claims are tested on one read, both frozen here. FIRST, the conditional severity model: its calibration was established on design-tier data with the estimator repaired the same day, so the honest question is whether the repaired estimator holds its stated coverage forward. SECOND, the condition signal: the loser leg's stated-condition rate was elevated at six of seven design tier episode dates against seven controls at a pre-registered one-sided p of 0.0175, and the question is whether that reappears at episodes the detector finds in the sealed years.

**Prediction, frozen before the run.** SEVERITY. On sealed-era forecasts at the declared 10-day horizon and 5 percent quantile, the conditional model's breach rate lies within the Clopper-Pearson interval around 0.05 and its unconditional-coverage test does not reject at 5 percent. If it breaches materially above 0.05 the model is overconfident out of sample and the severity row on the page is withdrawn to the unconditional twin. TEXT. Episodes are found in the sealed era by the registered event rule, and the loser leg's stated-condition rate at their formation dates exceeds the rate at matched sealed-era control months, in the same direction as the design-tier result. If it does not, the design-tier elevation is recorded as design-tier only and the memo says the elevation did not reproduce out of sample.

**What this test could and could not see.** Stated before the read and it is the binding limit. The sealed era runs 2023-01 to 2026-08, about 44 months, which at a 21-day forecast step gives roughly 40 severity forecasts and therefore about 2 expected breaches at a 5 percent rate. That is enough to detect gross miscalibration -- a breach rate above roughly 0.17 would reject -- and nothing finer, so a pass is weak evidence of calibration and a failure is strong evidence against it. The text arm is weaker still: the registered rule may find only a handful of sealed episodes, and with three or four against a similar number of controls no rank test can reach conventional significance. The text arm is therefore registered as DESCRIPTIVE, reporting per-date rates and their direction, and a null on it will be recorded as instrument-limited rather than as evidence the design-tier result was spurious.

**Result.** SEVERITY ARM PASSES on the registered design. At the 21-day forecast step the power statement fixed before the read, the conditional model breaches 1 time in 42 sealed-era forecasts, a rate of 2.38 percent against 5 expected, with an unconditional-coverage p of 0.388 and an interval of [0.0006, 0.126] containing 0.05. CORRECTED: this was first reported as 2 of 42 at 4.76 percent with p 0.943. Both callers of the severity model in that run divided an already-decimal market series by a hundred a second time, which leaves a quantile fit untouched because the fit is equivariant to rescaling a regressor, but flips the bear-state flag on 3.1 percent of days. Under the bug the conditional model's sealed coverage was IDENTICAL to the unconditional baseline's, to four decimal places and in both interval bounds, and that coincidence is the signal that should have been chased. It is logged in the trap register as a unit-conversion applied twice. The registered verdict is unchanged and the holdout still passes on the registered pass condition, because the interval contains 0.05 either way; what changes is that the conditional model is now DISTINGUISHABLE from the baseline it exists to beat, 1 breach against the baseline's 2, where under the bug it was numerically the same object. The corrected pass is weaker on p and more meaningful in what it separates, and the sentence about the registration predicting two breaches and getting exactly two is withdrawn: there was one. in advance: an interval spanning 0.6 to 16 percent would have passed too, so this rules out gross miscalibration and nothing finer. Two things make it worth more than the interval suggests. The sealed era was WILDER than the design era, 15.7 percent annualised against 12.4, and the model tracked that rather than under-forecasting into it. And the first implementation of this test deviated from the registered sampling, using 865 daily overlapping forecasts instead of the registered 21-day step, which reported a spurious FAIL at a 1.85 percent breach rate; the deviation is logged and the registered design is what is reported. Six sealed-era episodes were found by the registered event rule, at formation dates 2022-12-31, 2023-04-30, 2023-10-31, 2025-01-31, 2025-07-31 and 2026-04-30; the text arm runs on those. TEXT ARM: THE DESIGN-TIER ELEVATION DID NOT REPRODUCE. Across six sealed episodes and six matched sealed controls the loser leg's stated-condition rate has a median of 11.0 percent against 10.4, a gap of 0.6 points where the design tier gave 6.3, and a one-sided rank test of p = 0.4686. The direction is nominally the same and the effect is gone. This is stronger evidence against than an underpowered null would be: an underpowered test shows a large point estimate with a wide interval, and this shows no point estimate at all. The design-tier elevation is recorded as design-tier only.

**Reproduce.** `uv run python scripts/sealed_run.py`

### Is the 12-1 book more macro-concentrated than sorts on other trailing windows?

**Verdict: supported**  ·  registered 2026-09-03  ·  *in this package because it reproduces via `same_rule_null.py`*

**Hypothesis, frozen before the run.** The eight-series concentration test against random size-matched books cleared every month-end tested, with a median of seven of eight series above the family threshold and all eight above it on 44 percent of dates. That null is saturated: a momentum-sorted book differs from a random book on every macro axis at once, so a maximum over eight cannot discriminate. The informative null is not a random book but a book built by the same KIND of rule. If the design's claim is specifically about the 12-1 sort, its concentration should exceed what other trailing-return windows produce on the same date. If it does not, then "the sort confers a concentrated macro exposure" is a statement about return sorts in general and the 12-1 specification carries none of it.

**Prediction, frozen before the run.** On the same month-ends and the same eight reference series, the 12-1 book's maximum standardised concentration will exceed that of a 6-1 sort and a 24-13 sort more often than the one-in-three a three-way tie would give. The honest alternative, and the one I expect to be at least partly true, is that all three sorts are similarly concentrated and differ mainly in WHICH series carries their maximum -- each window loading on what its own window realised. That outcome refutes the concentration claim as a property of the 12-1 sort while supporting the mechanism claim that a return sort confers its own window's exposure, and both halves are reported.

**What this test could and could not see.** About 108 month-ends, but the three sorts share a universe and overlap in membership, so the dates are not independent draws and neither are the sorts. The comparison is therefore reported as a paired win rate with a sign test across dates rather than as a difference of means, and the detectable effect is a consistent ordering rather than a small gap. A win rate near one third is the tie outcome and will be reported as refuting the 12-1-specific claim rather than as an inconclusive result, because a tie IS the informative answer here.

**Result.** The 12-1 sort is more macro-concentrated than sorts on other trailing windows, and the margin is modest rather than decisive. Across 108 month-ends with a shared placebo pool per date so the three sorts are standardised identically, the median maximum standardised concentration is 23.77 for 12-1 against 18.43 for 6-1 and 15.79 for 24-13, and 12-1 is the most concentrated of the three on 42.6 percent of dates against the 33.3 a three-way tie would give, sign test p = 0.0278. The registered prediction is therefore supported, but the honest reading is that MOST of the concentration is generic to return sorting rather than specific to this specification: a nine-point edge over the tie rate means the other two windows are the most concentrated on 57 percent of dates between them. The half of the registration that anticipated a tie was closer to right than the half that anticipated a clean win. The second half of the prediction lands cleanly. The sorts differ in WHICH series carries their maximum: 12-1 loads on the first two principal components and the market (pc1 22 percent, pc2 16, mkt 15), while 24-13 loads on crude and the concentration spread (wti 17, concentration 17, usd 15), and 12-1 and 6-1 agree on the series only 42.6 percent of the time. Each window confers the exposure its own window realised, which is the mechanism claim, and it is now measured rather than asserted.

**Reproduce.** `uv run python scripts/same_rule_null.py`

### The crash inventory: does the three-route framework partition the episodes it claims to explain?

**Verdict: refuted**  ·  registered 2026-09-03  ·  *in this package because it reproduces via `crash_inventory.py`*

**Hypothesis, frozen before the run.** Section 1.4 claims that every large negative realisation in the momentum factor is a large negative realisation of one of three terms: the market term carried by the loser leg after a bear market (Route 1), the macro term carried by the winner leg (Route 2), or the residual term correlated across names (Route 3). Until every episode in the record is checked against that claim, the three routes are a story assembled from the literature and from three remembered dates. The claim is testable because the terms leave different traces in the leg returns themselves: a loser-leg rebound in a bear state, a winner-leg unwind with the market flat and no bear state, and a both-legs move that retraces. The French ten-portfolio daily file supplies decile returns from 1926, so leg attribution is available for the FULL history and not only for the reconstructed holdings era, which is more than the memo currently promises. The exact loss decomposition L = -(hi - lo) with winner share -hi/L and loser share +lo/L is arithmetic, not a model.

**Prediction, frozen before the run.** Most episodes will be assigned a route, and the assignment will be lopsided rather than even: Route 1 should dominate the pre-war and post-crisis rebounds and Route 3 should be rare in the fast definition because it is defined partly by retrace. I expect a non-trivial fits-none count, somewhere between five and twenty percent of episodes, and that count is the result that matters most. A fits-none share at or below five percent would mean the rule is loose enough to absorb anything and the partition claim is unfalsifiable as specified; a share above thirty percent would mean the framework does not describe the record and Section 3.7 gains a fourth mechanism it does not name. Both branches are written here before the run. I also predict that the leg-share discriminator separates the episodes more sharply than the market return during the window does, because the market return is the discriminator the literature uses and the leg shares are the one this framework adds.

**What this test could and could not see.** The fast definition on a century of daily data will admit on the order of one hundred episodes, of which roughly fifteen fall in the reconstructed-holdings era. The census needs no power. The fits-none band does: at one hundred episodes a five-percent share has a binomial interval of roughly two to eleven percent, so the design can distinguish a rule that absorbs everything from one that leaves a real residue, but it cannot resolve a fits-none share of eight percent from one of twelve. The reconstructed tier at fifteen episodes can support no inference at all on its own and is reported as a table, not a test. Any statement about route frequencies changing over time is out of scope at this sample and will not be made.

**Result.** The three-route framework does not partition the record as specified. The registered event definitions admit 195 episodes from 1926 to 2026, 164 by the fast ten-day rule and 31 more the slow rule found alone, and every one of them has leg attribution because French's ten-portfolio daily file reaches back to 1926. The rule assigns Route 1 to 63 and Route 2 to 44 and leaves 86 unassigned, a fits-none share of 44.6 percent with an interval of [37.4, 51.9]. Two further episodes carry NO-DECOMPOSITION: they are real factor episodes the decile file barely registers, so their leg shares divide by a denominator near zero and were -34.7 and +5.7 before a validity condition on the ratio excluded them. That condition is post-hoc, it was added after a reviewer found the rows, it moves the headline from 44.1 to 44.6 percent, and it changes no verdict. The registered band was 5 to 30 percent and the registered sentence for a share above 30 was that the framework does not describe the record, so that sentence publishes. The residue is a shape, not noise, and this is the part worth reading. 77 of the 86 unassigned episodes -- 89.5 percent of them -- fail in exactly the same way: the loser leg drove the loss, with a median loser share of 1.13, the market ROSE during the window in 72 of 86, and there was no bear state. 71 of those 77 would be Route 1 if the bear-state clause were dropped. The clause that breaks the partition is the one inherited from the crash literature, and section 1.4 already says in prose what the rule failed to encode: "the same leg can fire without the market moving at all". The modal reversal in the record is a loser-leg repricing in a rising market with no bear market behind it. Route 3 never fires. Zero episodes of 195 meet its definition, and the three clauses never co-occur: 21 episodes had a flat market, 16 had both leg shares inside the band, 80 retraced at least half within twenty sessions, 8 were flat and in-band, 5 were flat and retraced, none were all three. A synthetic Route 3 episode planted at the centre of the clause space is typed Route 3, so the zero is a statement about the record and not a bug. August 2007, the memo's type case for Route 3, is typed ROUTE 2 by the rule: winner share 1.32, market down 1.76 percent, no bear state, and 145 percent of the loss retraced inside twenty sessions. The rule finds the mechanism it was built from. 1932 gives six Route 1 episodes of eight and 2009 gives five of five. What it cannot find is the modern one: across the whole 2010s the inventory holds 21 episodes, of which 0 are Route 1, 2 are Route 2 and 19 fit no route. And the flagship date of the whole memo is in the residue. 2020-11-18 is FITS-NONE, because the trailing two-year market was up 33.8 percent and the bear-state clause fails, while the loser share is 1.19 and the market rose 6.5 percent through the window -- the residue's modal case exactly. It is also one of only three episodes in a century that contain a day at or below the registered crash-day threshold of -933bp; the other two are September and November 1939, and all three are unassigned.

**Reproduce.** `uv run python scripts/crash_inventory.py`

### Do the route detectors, read at the formation date, recover the route the episode turned out to be?

**Verdict: instrument_limited**  ·  registered 2026-09-03  ·  *in this package because it reproduces via `crash_inventory_score.py`*

**Hypothesis, frozen before the run.** A partition is not a system. The system's claim is that the route can be read at the formation date from the detectors of Table 3, ahead of the event, from data available then. If the detectors' formation-date readings agree with the routes the crash inventory assigns by rule, the detectors are anticipatory. If they agree no better than chance, they are descriptive: they can label a reversal after it has happened and cannot type one before. The routes this is scored against are the ones the crash inventory assigns by rule, listed in the `needs` field.

**Prediction, frozen before the run.** I expect agreement above chance and well below anything decisive, and I expect Route 1 to be recovered better than Routes 2 and 3, because Route 1 is the only one whose detector reads a condition stated in advance rather than a property of returns. Route 3's detector is the one I expect to fail, because Section 3.2 already states it is blind until crowding has moved prices. Chance is one in three across three routes.

**What this test could and could not see.** This is the binding constraint and it is stated before the run rather than discovered after. At twelve scorable episodes against a one-in-three null, eight hits are needed for a one-sided exact binomial p below 0.05, which is an agreement rate of 0.67. The design can therefore detect only a large effect. A result of five or six of twelve is the modal outcome under a genuine but moderate effect AND under the null, and will be reported as instrument-limited under the floor rule of Section 5.1, not as a refutation. The registered pass level is 0.67; anything below it publishes the sentence that the detectors are descriptive rather than anticipatory at this sample, with the interval printed beside it.

**Result.** The detectors agree with the rule-assigned route on 4 of 7 scorable episodes, an agreement of 0.571 against a one-in-three null, one-sided exact binomial p = 0.173. The registered pass level was 0.67 and 5 of 7 was the smallest count that would have cleared p = 0.05, so this neither clears the level nor refutes the claim. It is the outcome the power statement named in advance as modal under both a genuine moderate effect and the null, and the floor rule of section 5.1 governs: the sentence that publishes is that the detectors are DESCRIPTIVE rather than anticipatory AT THIS SAMPLE, with the count printed beside it. Three things about the run are worth more than the headline. The sample is the finding. The registration assumed about twelve scorable episodes across three routes. The census produced 30 episodes in the reconstructed era, of which only 8 carry a route at all -- 22 are FITS-NONE -- and one of those 8 has a formation date of 2014-03-31, before the 8-K corpus begins in 2018, leaving 7. Route 3 has no instances anywhere in the record, so a three-class argmax was scored against a truth set containing two classes. Three extraction runs were commissioned to fill the Route 1 detector on the design-tier formation dates that lacked it, at 2021-01-31, 2021-03-31 and 2021-06-30, and all three read cleanly: 154, 221 and 170 filings, zero errors, stated-condition rates of 18.2, 8.1 and 8.8 percent. The registered direction is wrong. The registration predicted Route 1 would be recovered better than Routes 2 and 3, because Route 1 is the only detector reading a condition stated in advance rather than a property of returns. It was recovered on 1 of 3 while Route 2 was recovered on 3 of 4, and the argmax lands on Route 2 on 5 of the 7 dates. The detector set is biased toward Route 2, and the prediction that was written down is the one that failed. Route 3's detector never wins. Its standardised reading is BELOW its own trailing band on every one of the seven dates, with a maximum of -0.228. That is an independent second sign of what the census already showed: within-leg co-movement, read at formation, carries no signal that a crowded exit is building. Section 3.2 says the Route 3 detector is blind until crowding has moved prices, and this is that statement measured rather than asserted.

**Reproduce.** `uv run python scripts/crash_inventory_score.py`

### Does the analogue comparison survive being made two-sided, and do a date-constrained and a contemporary encoder rank the same episodes?

**Verdict: supported**  ·  registered 2026-09-03  ·  *in this package because it reproduces via `analogue_rag.py`*

**Hypothesis, frozen before the run.** The analogue panel's record is one-sided and this is visible in the committed artifact. The query side carries nine extracted conditions with verbatim spans; every retrieved neighbour carries only a date, a distance, a block closeness and a forward return. When the adjudicator ruled the 2009 match not apt because "every retrieved state is a credit-crisis recovery", it was comparing the query's RECORD against the model's MEMORY of 2009, and section 3.8 already concedes the general form of this: the dissent cited real fields while making claims about fiscal stimulus and circuit breakers that reached past them into world knowledge. The field gate could not catch it because the cited field was real. The repair is to give each candidate episode its own condition record. 3,625 filings have already been read across 28 formation dates and 419 records carry a grounded verbatim span, so the corpus exists and is pre-verified by the quote gate. With conditions on both sides a mechanism claim has a field to cite, and a mechanism claim about an episode with no record has none, so the existing gate drops it by the rule it already applies. Reading that corpus needs an encoder, and an encoder is where lookahead enters. A frontier encoder trained after 2020 knows what followed the conditions it is reading; this project has already measured that stripping dates does not hide the date, a model placing the exact year in 40 of 40 anonymised cases. So the corpus is read TWICE: once by a chronologically consistent checkpoint whose training cutoff precedes the query date, and once by a contemporary sentence encoder that has seen everything. Their rank agreement is the measurement the register has been carrying as row 09, unrun.

**Prediction, frozen before the run.** Two arms, two predictions, both written before either runs. ARM A, the gate. With conditions on both sides, mechanism claims about pre-2018 analogues have no field to cite and must be dropped. The corpus begins 2018-09-30, so at the flagship query date the 2009, 2008 and 2000 neighbours carry NO RECORD and every claim about what they were priced on should fall. I predict the adjudicator reaches the same not-apt verdict it reached before, by a different and checkable route: not "2009 was a credit crisis" from memory, but "no condition record exists for 2009, so mechanism cannot be ruled on". That is a weaker-sounding output and a stronger one. The positive control is planted: six mechanism claims, three citing a condition field that exists for a covered episode and three citing one for an uncovered episode, and the gate must keep exactly the first three. ARM B, register row 09. Spearman rank agreement between the two encoders over the candidate pool, per query date, with the registered pass at 0.80 and read TWO-SIDED. Below 0.80 the contemporary encoder is ranking on something the constrained one cannot have, which is measured lookahead, and the feature is restricted to the constrained encoder with the size of the gap printed. Above roughly 0.98 the constrained reader adds nothing beyond the cheap one and the seat is idle under the twin rule, which retires it. Between them the agreement bounds how much of the ranking is recognition rather than reading, both are reported, and the constrained encoder is the one whose ranking reaches the page. I expect the middle branch and would not be surprised by the third, because condition texts are short noun phrases and a verbatim span rather than the long-form narrative where an encoder's world knowledge has room to express itself.

**What this test could and could not see.** Arm A is a positive control with six planted claims and a known correct answer; it can fail outright and cannot be underpowered. Arm B is the constrained one. Twenty-eight formation dates carry records, of which thirteen coincide with an inventory episode, and the candidate pool at any one query date is smaller still after the one-year embargo. A Spearman correlation over roughly twenty candidates has a standard error near 0.22 at rho = 0.8, so a single query date cannot separate 0.80 from 0.65, and no such separation will be claimed. What the design CAN do is distinguish broad agreement from near-independence, and it can report the distribution across query dates rather than one number. If the median lands inside the band with a spread that crosses 0.80, that is reported as the interval crossing the threshold and row 09 stays open, not as a pass.

**Result.** ARM A PASSES and the gate fired on a live run for the first time. With conditions on both sides, six planted mechanism claims were put through the sharpened gate: three about episodes that carry a condition record, each with a span lifted verbatim from it, and three about episodes that do not. It kept exactly three, and exactly the right three. On the live panel at 2020-10-31 the dissent then attempted a mechanism claim about 2018-12-31 with no grounded span and the gate dropped it -- the first time this gate has fired outside a planted test, where the previous run had 8 of 8 claims pass and demonstrated nothing. The predicted verdict is the one that came back, by the predicted route. The registration said the adjudicator would reach the same not-apt conclusion "not because 2009 was a credit crisis from memory, but because no condition record exists for 2009, so mechanism cannot be ruled on". It returned state_match_is_apt false, mechanism_is_rulable false, failing on condition_record_status, and its reasoning cites that field. All five state-space neighbours of the flagship date are pre-2018 and carry NO RECORD, so the panel now says what it cannot know instead of asserting what it remembers. ARM B, register row 09, DOES NOT CLOSE, and the registration said in advance that this is how it would be reported. Across 22 query dates the median Spearman agreement between the date-constrained checkpoint and the contemporary encoder is 0.846 with a bootstrap interval of [0.771, 0.900]. That interval CROSSES the registered 0.80, and the power statement committed to reporting a crossing interval as the row staying open rather than as a pass. 68.2 percent of dates clear the threshold. The structure inside that number is the finding. Agreement falls sharply as the candidate pool grows: the rank correlation between pool size and agreement is -0.629 at p = 0.0017. On the eight small pools of four to eight candidates the median agreement is 0.900 and every date clears 0.80; on the fourteen pools of twelve or more it is 0.778 and only half clear. Small pools admit few orderings, so the early agreement is partly mechanical, and the honest reading is that at realistic pool sizes the two readings come apart. And the number that matters most for a system whose output is a nearest analogue is worse than the median suggests. The two encoders agree on WHICH episode is nearest on only 31.8 percent of dates overall -- 62 percent at small pools and 14 percent at pools of twelve or more. At realistic sizes the constrained and contemporary readers disagree about the nearest episode roughly six times in seven, and the nearest episode is the one that reaches the page.

### Does dividing by trailing volatility, and then conditioning on the bear state, improve a ten-day 5 percent quantile forecast of the momentum factor?

**Verdict: refuted**  ·  registered 2026-09-04  ·  *in this package because it reproduces via `poc_e1_tail.py`*

**Hypothesis, frozen before the run.** The design specifies a tail model with no fitted parameters: the 5 percent quantile of past ten-day returns, each divided by the volatility at the time, taken over past starts in the same state as today and multiplied by today's volatility. Two published results motivate the two ingredients. Barroso and Santa-Clara show that scaling momentum by trailing realised volatility roughly doubles its Sharpe ratio and removes most of its negative skew, which says the conditional scale is forecastable. Daniel and Moskowitz show the worst losses cluster in high-volatility rebounds after bear markets, which says the conditional shape depends on a state beyond scale. ### The theme pipeline: does a component's companies concentrate on one risk theme that random books do not?

**Verdict: instrument_limited**  ·  registered 2026-09-04  ·  *in this package because it reproduces via `poc_e7_theme.py`*

**Hypothesis, frozen before the run.** The design's claim is that on a formation date before an episode, the companies carrying a named component's exposure state, in their filings, one shared risk theme that the same number of randomly chosen companies do not; and that on calm dates nothing rises above that placebo. Nothing of this pipeline exists. Every text result so far is from a different instrument -- a document-level extractor for survival conditions on the loser leg -- and none of it tests this claim.

**Prediction, frozen before the run.** On at least five of the eight episode formation dates a theme rises above the 95th percentile of the random books' maximum excess weight, and on the three calm windows none does. The labels on the episode dates should be recognisable as the episode's, and the expected labels are written down before the run: vaccine or treatment timing before 2020-11, tariffs before 2025-04, inflation and rates before 2022-11. The honest alternative is that themes rise above the placebo on calm windows as often as on episode windows, which would mean the pipeline detects clustering in filings generally rather than anything about reversals, and the fail sentence publishes. A third outcome, and the one I think most likely given how small the sample is, is that the result is neither clean: some episodes fire and some calm windows do too, at a count this design cannot separate from chance. Eight against three is a very small comparison and the power statement says so.

**What this test could and could not see.** Eight episode dates against three calm windows. Under a null where each date clears the 95th percentile with probability 0.05, five of eight is far beyond chance, so the arithmetic bar is easy and the binding uncertainty is elsewhere: three calm windows cannot distinguish a base rate of zero from one of a third, so the control side of the comparison is nearly uninformative. The design can show that themes rise on episode dates; it cannot show that they fail to rise on ordinary ones. That asymmetry is stated now and will be stated in the result whichever way the counts fall. The label-matching claim needs a rule fixed in advance: the expected label per episode is written into this registration, and a match is counted only where the theme's terms overlap the expected label's terms. No post-hoc judgement of recognisability is admitted.

**Result.** THE COMPARISON THE REGISTRATION DESCRIBES COULD NOT BE MADE, and the reason is coverage rather than the placebo. The pipeline was built and ran end to end on all twelve dates: the book, 200 cell-matched random books per date, Ledoit-Wolf on the market residual, three sign-fixed components, the bridge, the encoder, the clustering, the leg-sign assignment and the excess weight against the random books' maximum. Nothing was skipped. THE EPISODE SIDE FALLS SHORT OF ITS OWN BAR. A theme rose above the 95th percentile of the random books' maximum on 2 of 8 episode dates against a registered prediction of at least 5, and on 0 of them did the label match the expected label written into this registration before the run. THE CONTROL SIDE CARRIES NO INFORMATION AT ALL, which is the finding that decides the verdict. Of the three calm windows one is unbuildable -- the panel holds 22 observations in the 126-day window against a declared minimum of 100 -- and the two that build have essentially NO component-set company with a point-in-time Item 1A: the per-component counts are [0, 0, 0] at 2016-08-31 and [0, 1, 0] at 2018-08-31. A component set with no covered company cannot produce a non-zero excess weight, so "no theme rose on the calm windows" is arithmetic, not evidence. The eight-against-three comparison has a control side that could not have gone the other way. COVERAGE IS THE BINDING LIMIT THROUGHOUT. Across twelve dates the book's own component set holds between 0 and 25 companies with a point-in-time Item 1A against set sizes of 116 to 137, so every excess weight rests on at most a fifth of the set's absolute loading and usually on a few per cent. The two episode themes that did rise rest on 1 of 137 companies (2019-08-31, "patents", excess +0.0047 against a threshold of +0.0046) and 11 of 132 (2020-12-31, "company, bank, incorporated"). Neither is its episode's theme by the registered term rule, and the first clears its threshold by one part in ten thousand on a single company. AND THE CLUSTERER IS NOT STABLE. On 2020-10-31 the primary configuration returned 2 clusters with one holding 97.8 percent of 2,850 statements. The diagnosis was run before the result was recorded and exonerates the date: the reduction ran, the seed is fixed, the boilerplate rule fired. Three independent 64-company draws from that same date's own filings, at identical parameters and seed, returned 2, 2 and 26 clusters, and a 2,200-sentence draw from the same corpus returned 24. No parameter was changed to obtain any of those. A declared degeneracy flag fires on that date and on no other, and the flagship date is the one it fires on. The registered configuration -- HDBSCAN at minimum cluster size 25 in raw 384 dimensions -- returns nothing at all on all twelve dates, noise share 1.000, which is the known high-dimension failure and is reported beside the reduced-space variant rather than replaced by it.

### trp-79 · A parser skipped a third of an archive on encoding errors, and a link filter removed the crash months.

**What happened.** Two independent faults in one acquisition, both of which produce silence rather than an error. The parser caught decode failures and printed a skip line per file, which looked harmless because only the last few were visible on screen; it had in fact dropped about two thirds of the archive, 6.7 million rows against the 18.2 million actually present, and 1,145 settlement dates against 3,305. Separately, the SEC index serves these files under four path prefixes, one of which reads like a content-management artefact rather than a data path. That prefix was filtered out of the download list as junk. It is the real location of six half-month files covering February, March and April 2020, so the archive was missing exactly the COVID crash, which contains a registered episode.

**Why it parsed.** Both faults present as an absence. A dropped half-month does not raise, does not appear as a null, and downstream reads as a period with no settlement stress -- that is, as a calm market. The coverage check that caught the second fault only worked because it compared against a continuous month range rather than against the file list, which was itself wrong. Checking the downloaded files against the download list would have passed, since the list was the thing that was incomplete.

**The defence.** A parser must raise on a file it cannot read rather than continue, because a missing period and a quiet period are indistinguishable once the data is in memory; decode is now attempted across several codecs and only an unreadable file stops the build. A link filter must never drop a candidate on the grounds that its path looks wrong -- if a prefix appears in the index it is a location, and the only safe test is whether the fetched bytes are the expected format. Coverage is verified against a continuous calendar built from the data's own span, never against the list used to fetch it.

### trp-80 · A committed result panel no longer reproduced from its own generator and nobody had re-run it.

**What happened.** Regenerating the placebo panel behind the mechanism claim moved it from 104 of 128 months clearing to 105 of 137. ### trp-81 · The conditional expected shortfall was not conditional, so it read milder than the VaR beside it.

**What happened.** On the page for 2020-10-31 every expected-shortfall figure was less severe than the value-at-risk printed next to it -- a 10-day 5 percent VaR of -0.0947 against an ES of -0.0586 -- contradicting the sentence printed directly beneath, that ES is the average loss given the VaR is breached and is therefore always the worse number. The same block was correct at 2019-09-06, so it presented as date-specific rather than as a formula error.

**Why it parsed.** The two quantities were different objects wearing one label. VaR was evaluated at today's state; ES was the mean realised return below the in-sample fitted quantile across the whole training set, which does not depend on today at all. Whenever the current state is more extreme than the sample average the VaR moves and the ES does not, and the inequality inverts. The field was named es_conditional and the docstring described what the code did rather than what the name claimed, so reading either one in isolation looked consistent.

**The defence.** Estimate the tail's MULTIPLICATIVE severity in-sample -- how much worse an exceedance is than the quantile it breached -- and apply that ratio to today's VaR. The ratio is at least one on the rows it averages, so the ES can no longer come out milder than the VaR. More generally: when two numbers are printed side by side under a stated inequality, that inequality is an assertion about the code and belongs in a test.

### trp-82 · A result cache keyed on its inputs but not its estimator served stale numbers after the model was fixed.

**What happened.** After the conditional expected shortfall was repaired, the page reprinted the inverted values byte-for-byte at both test dates. ### trp-83 · A family-wise correction raised the pass rate to 100 percent, because the null was saturated.

**What happened.** The eight-series version of the concentration test cleared 108 of 108 month-ends. The first implementation used the maximum PERCENTILE across series, which saturates: against 200 draws a percentile has half-a-point resolution and the real book exceeds every placebo on at least one of eight series essentially always, so the real book pinned at 100.0 on 107 of 108 dates while each placebo capped at 99.5 by being included in its own comparison. Replacing it with a continuous statistic, the maximum standardised distance with leave-one-out moments, fixed the arithmetic and did not change the verdict: still 108 of 108, with a median maximum z of 22.8 against a threshold of 2.74.

**Why it parsed.** A multiple-testing correction is expected to make a test HARDER, so a correction that raised the pass rate from 76.6 percent on one series to 100 on eight should have been implausible on sight. It was not caught by any check; it was caught by the round number. The deeper cause is that the null is too weak for the statistic: the median date has SEVEN of eight series above the family threshold and on 44 percent of dates all eight are, because a momentum-sorted book differs from a random size-matched book on every macro axis at once. A maximum over eight saturated quantities cannot discriminate.

**The defence.** Read the direction of a correction before reading its result: a family-wise adjustment that increases a pass rate is either a coding error or evidence the null is saturated, and both need finding before the number is quoted. The single-series test discriminates at 76.6 percent partly by accident of which series was registered -- market beta carries the LOWEST median z of the eight at 7.8 against 18.7 for the first principal component, so a different registered series would have cleared near 100 percent as well. The informative null for a concentration claim is not a random book but a book built by the same kind of rule: sorts on other trailing-return windows, which this design already names as its live control and had not run.

### trp-84 · A sealed test deviated from its own registered sampling and produced a spurious failure.

**What happened.** The holdout's severity arm was registered with a power statement naming a 21-day forecast step, roughly 40 forecasts and about 2 expected breaches. The script that read the seal used DAILY forecasts instead, 865 of them, each a 10-day window overlapping the next by nine days. It is the same overlapping-windows error this project criticises elsewhere, committed inside the one test whose entire value depends on being run exactly as written. Had the direction of the artifact been flattering rather than damning it would have been far harder to catch, because the instinct that saved it was disbelief at a failure, not a rule.

**The defence.** A pre-registration that fixes a sampling scheme has to be executed by the code, not remembered by the person running it: the registered step belongs in the script as a constant read from the registration, so a deviation is a diff rather than an oversight. And a sealed test is exactly where post-hoc flexibility is least acceptable -- the defence for reporting the 21-day result is that the step appears in a registration committed before the read, and that defence would be worthless if the number had been chosen after seeing both.

### trp-85 · A registered secondary statistic compared a label against the variable that defines it.

### trp-86 · The page the memo says is machine-composed and numeral-checked is hand-typed.

**What happened.** Section 2.1 states as a principle that deterministic code produces every statistic on the page and that a tokeniser rejects any page where a numeral in the prose fails to match a computed field, and Appendix D gives the composer role a numeral canary whose one mismatch fails the build. Neither exists in code. ### trp-87 · A market series divided by a hundred twice made a conditional model equal its own baseline.

**What happened.** The French loader already converts percentages to decimals, so a caller that divides the market series by a hundred again scales it by a further hundred. Two callers did: the sealed holdout script and the severity command line. A linear quantile fit is equivariant to rescaling a regressor, so the fitted values are untouched and the bug is invisible in every output that depends only on them. The bear-state indicator is not: it is a sign test on a compounded trailing return, and it flips on 3.1 percent of days between the two scalings. The consequence lands on a headline. On the sealed holdout at the registered forecast step the conditional model breached 2 of 42 at a rate of 4.76 percent with an unconditional coverage p of 0.943 -- numbers identical, to four decimal places and in both interval bounds, to the UNCONDITIONAL baseline computed on the same dates. Under the corrected scaling the conditional model breaches 1 of 42 at 2.38 percent with p 0.388, and the baseline still breaches 2. The registered verdict is unchanged and the holdout still passes, because the interval contains 0.05 either way. What changes is that the model is now distinguishable from the baseline it is supposed to beat, where under the bug it was numerically identical to it.

**Why it parsed.** Every consequence of the bug was either invisible or flattering. Scale-equivariance hid it from the fitted values, which is most of what anyone inspects; the bear flag it did corrupt is a binary column nobody reads directly; and the corrupted result was CLOSER to the nominal rate than the correct one, so the pass looked stronger rather than weaker. The one signal that something was wrong -- a conditional model reproducing its own baseline to four decimal places -- is the kind of coincidence that reads as reassuring agreement rather than as a defect, and it sat in a committed artifact through a full write-up.

**The defence.** A loader that has already converted units should say so in a way a caller cannot miss, and the conversion should happen once, at the boundary, rather than being reapplied on trust. Beyond that: when a conditioned model and its unconditional baseline agree to four decimal places on the same sample, that is a finding to chase and not a result to report. The comparison is cheap, it is the whole point of printing a baseline, and nothing in the process forced anyone to look at the two numbers side by side until a separate check made it unavoidable.

### trp-91 · A published weight column rounds to zero, and dropping the zeros deletes the leg's whole point.

**Why it parsed.** This is the same censored-column fault already logged for the book's weights, at a second site nobody had looked at, and it is invisible for the same reason: zero is a legitimate weight, so nothing raised, and the matching still produced ten buckets of the right size. A tie-breaking rule that silently orders half the data alphabetically leaves no trace in any summary statistic of the match.

**The defence.** When a matching variable has ties, the count of tied values belongs in the match's own diagnostics, and a match on a variable that is constant across half the sample should fail loudly rather than partition on index order. More generally, once a censored column has been found in one place, the fix is to grep every consumer of that column rather than to repair the site where it was noticed.

### trp-94 · The page cited a calibration computed on its own future, then described it wrongly.

**What happened.** The example page for the 2020-10-30 formation printed the scaled line's coverage as 6 breaches of 81 at a Kupiec p of 0.352 and the unconditional line's as 11.11 percent at 0.028, and concluded in prose that the unconditional quantile is the miscalibrated one. Both figures are computed over the whole design tier, which runs to December 2022. A page dated October 2020 cannot cite a statistic that uses two more years of its own future. Recomputed on formations strictly before the page date the two lines are IDENTICAL: 5 breaches of 54, 9.26 percent, Kupiec p 0.197, for both. They breach on the same formations. So the sentence saying the unconditional line was miscalibrated was not merely unsupported at that date, it was false; the divergence appears later in the tier and a reader standing on the page date could not have known it. The words "passes" and "fails" were also typed into the prose beside the numbers rather than derived from them, which is how the contradiction survived being read.

**Why it parsed.** The numeral canary passed the page, because every numeral on it did resolve to a registered computed field -- the fields were simply computed over the wrong window. The canary checks NUMBERS and not CLAIMS, and a verdict word is a claim: "fails" beside a p of 0.197 is a hand-typed conclusion that no numeral check can see. The point-in-time discipline the project applies rigorously to model inputs had not been applied to a statistic quoted on an output.

**The defence.** Anything a page asserts about its own reliability must be computed on data available at the page's date, exactly as its inputs are, and the register's later figure is a different claim that has to be labelled as later. Verdict words must be derived from the statistic in code and never written into prose, so a sentence cannot drift from the number beside it. And the canary should be understood for what it is: a guarantee about provenance of numerals, not about the truth of the sentences containing them.

### trp-95 · Market value was computed from split-adjusted prices times unadjusted share counts.

**What happened.** Position weights were built as price times quantity using the SPLIT-ADJUSTED price series. Split adjustment rescales prices backwards through the history, so multiplying an adjusted price by the unadjusted share count on the holdings file is not a market value and is not anything: it is the market value scaled by the cumulative split factor since that date. On a name that later reverse-split, the error is large and one way -- a single position took a twentyfold weight. The weight norm at 2017-12-31 moves from 0.6748 to 0.3785 once caps and weights are taken from raw prices while returns keep the adjusted series. This is the same figure a reviewer had flagged as suspicious thin-panel concentration. It was neither thin panels nor concentration; it was a units error inside the weight.

**Why it parsed.** Both series are prices, both are positive, and the product has the right shape and roughly the right order of magnitude for most names, because most names never split. The error is invisible except on the minority that did, and there it looks like a genuinely concentrated position rather than a mistake -- which is exactly how it was first diagnosed. Adjusted prices are the correct input for RETURNS, so the series was right for the calculation next to it.

**The defence.** Adjusted and raw price series are different quantities and should not share a variable name. Returns take the adjusted series; capitalisations, weights and anything ranked by size take the raw one. A weight whose norm moves by a factor approaching two when the price convention changes is the diagnostic, and comparing the two conventions on the same date should be a standing check wherever a weight is built.

### trp-96 · The news windows for each episode were mostly dated after the formation they informed.

**What happened.** The stored GDELT episode files span roughly two months before the event to two weeks after it, because they were assembled to describe episodes rather than to inform formation dates. Between 60 and 94 percent of the titles in each file postdate the formation date the theme pipeline was reading them for. Used unfiltered, the theme on a formation date would have been built substantially from news published after it -- the cleanest possible look-ahead, inside the one input whose whole justification is that it is timestamped. Titles after the formation date are now dropped, which is what leaves several dates with too few news statements for any cluster to reach the design's minimum membership.

**Why it parsed.** The corpus was built for a different purpose and was correct for that purpose, so nothing about the files was wrong. The point-in-time discipline this project applies rigorously to prices, holdings and filings had not been applied to the news corpus, because the corpus was inherited as an episode description rather than as a feature input. A window named after an episode invites the assumption that it precedes the episode.

**The defence.** Any corpus promoted from description to feature has to be re-dated against the date it will inform, not against the event it was collected for, and the share of records that survive that filter belongs in the record. The general rule this project already applies elsewhere is that availability is a property of the use, not of the file.

### trp-97 · The page's provenance labelled every repeated numeral with one field, so a reader clicking a number could be told the wrong thing about it.

**What happened.** `Registry.by_text()` returned one field per rendered string, so when several registered fields render the same text the last one registered silently won. On the 2020-10-30 page that put a single label on 30 of 67 numeral occurrences: both lines' 9.26% breach rate carried the unconditional line's label, both Kupiec p values of 0.197 carried the unconditional line's, and the two 263s -- names in the long leg and names in the short leg -- carried the loser leg's. The printed values were all correct and the canary reported PASS, because the canary asks whether a numeral matches a computed field and every one of them did. What was wrong was the answer given to a reader who asked which field.

**Why it parsed.** A dict keyed by rendered text always builds, and a collision is a silent overwrite rather than an error. The page reads correctly, the check passes, and the defect is visible only by clicking a number and reading a label that belongs to a different number. It is worse than an unlabelled figure precisely because the provenance file is the artifact that makes the page traceable: a wrong label there reads as traced.

**The defence.** Nothing in the page's own text distinguishes one occurrence of `9.26%` from another, so the matcher cannot resolve them and must not pretend to. `by_text()` now returns every candidate field and `_resolve()` marks the occurrence AMBIGUOUS, listing each candidate with its label and its reproduce command. Nine occurrences on the current page say so. The general rule: where an index can collide, the collision is reported, not resolved by registration order. A provenance layer may say "I cannot tell"; it may not guess.

### trp-98 · A shipped deliverable quoted an extraction result from a scratch log, and the numbers belonged to no run that exists.

**What happened.** The package's AI-use log printed the model-versus-rule comparison as recall 21.7% against 60.0% and specificity 100.0% against 60.0%. Neither pair is in any committed file. The registered arm, reports/poc/e4_summary.json, gives recall 19.2% against 54.2% and specificity 97.5% against 62.5%; the superseded incongruous-plant design gives 16.7% against 63.3% and 100% against 60%. So the specificity pair was the SUPERSEDED run exactly and the recall pair was neither run -- the table had been copied from a scratch log of an intermediate execution whose outputs were never committed. The direction of the finding survived, which is why it read as plausible: the rule beats the model on recall and loses on specificity in every version. A reader reconciling the deliverable against the artifacts found it, not any check here.

**Why it parsed.** Every other number in the package is rendered from a committed artifact at build time. This document was written by hand as prose, so nothing rendered it and nothing checked it, and a markdown table of plausible percentages looks identical whether or not the file it came from still exists. The fault is worse for its location: it was committed INSIDE the document whose subject is how each output was checked, in a package that has a section explaining that an earlier README went stale for exactly this reason.

**The defence.** A number in a shipped document is either rendered from an artifact at build time or it is a hand-typed number waiting to go stale, and prose is not an exemption -- the numeral canary covers the page and the README template covers the README, while this file had neither. The AI-use log is now a template rendered from reports/poc/e4_summary.json like the README, so a renamed or missing field stops the build. The second rule: where two runs of one experiment exist, the artifact naming says which is registered and which is superseded, and the rendered text names the file it came from so a reader can reconcile it in one step rather than by pattern-matching percentages across two files.
